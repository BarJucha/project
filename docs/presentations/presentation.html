01 • Title & Motivation

Decentralized Graph Navigation:
Preventing Action Cycles & Community Trapping

How can autonomous agents forward messages across complex networks using strictly local observations without getting trapped?

✕
Why Centralized Search Fails in Practice

Classical shortest-path algorithms assume a complete global connectivity map-an assumption that breaks down in real-world networks:

  • Privacy Restrictions: Peer-to-Peer (P2P) systems and social graphs forbid centralizing user connections.
  • Dynamic Topologies: Mobile ad-hoc and Internet of Things (IoT) networks change faster than global maps can sync.
  • Memory Bottlenecks: Storing global routing tables does not scale to massive graphs.
🌐
The Decentralized Routing Paradigm

Inspired by Milgram's small-world routing, nodes forward a message hop-by-hop with zero global visibility:

  • 1-Hop Local Visibility: Each node inspects only its immediate 1-hop ego-neighborhood and target attributes.
  • Privacy & Scalability: Requires zero global coordinates, central servers, or precomputed routing directories.
  • The Fundamental Dilemma: Without a global map or past memory, local decisions trigger loops & cluster traps.

02 • Problem Intuition

Local Navigational Signals vs. Partial-Observability Traps

Decentralized walkers rely on structural cues to reach distant targets—but those same structures create topological traps when agents lack history.

🧭
How Local Routing Works
  • Network Homophily: Nodes with similar attributes tend to connect directly—allowing greedy attribute similarity toward the target.
  • Structural Heterogeneity: Networks organize into dense local communities linked by sparse weak ties and high-degree hubs.
  • The Critical Bottleneck: Reaching an unknown community requires crossing a narrow bridge tie. A walker attracted purely to local similarity repeatedly loops inside dead-end clusters.

03 • Foundational Paper (1 / 2)

Reinforcement Learning for Decentralized Graph Path Search

"Reinforcement Learning Discovers Efficient Decentralized Graph Path Search Strategies" — Pisacane, Darvariu & Musolesi (Learning on Graphs (LoG) 2024), introducing Graph Attention-guided Routing for DEcentralised Networks (GARDEN)

1
Problem Formulation
  • Decentralized Partially Observable Markov Decision Process (Dec-POMDP): Each node hosts an autonomous agent with feature vector xu.
  • 1-Hop Observations: Message holder inspects neighbor ego-subgraphs Gu' + target subgraph Gu_tgt.
  • Sparse Terminal Reward: +1 on target arrival; truncated at Tmax = 100 (0 reward).
2
Training Paradigm
  • Centralized Training with Decentralized Execution (CTDE): Agents share parameters globally during training, then act independently using local observations.
  • Advantage Actor-Critic (A2C): Reinforcement Learning (RL) policy & value Multi-Layer Perceptrons (MLPs) trained end-to-end.
3
GARDEN Encoder
  • Learned Neighborhood Embeddings: Replaces raw attributes with topology-aware continuous representations.
  • 3-Layer Graph Attention Network (GAT): Encodes 1-hop neighborhoods into continuous vectors xuGAT.
  • Hidden Metric Space: Aligns attributes and connectivity to approximate latent shortest-path geometry.

05 • The Critical Gap & Primary Research Question

Why GARDEN Gets Stuck: Memory-Less Search → Primary Research Question

Analyzing the root cause of GARDEN's 40–48% timeout rate exposes the foundational gap driving this project.

⚠
Memory-Less Limitation in Pisacane et al. (2024)
  • Zero History Representation: The roaming packet carries only the static target representation m = xu_tgtGAT.
  • Blind to Past Failures: Agents have no record of visited nodes or failed subgraphs—the exact same action distribution repeats whenever a node is re-entered.
  • Inevitable Outcome: Deterministic ping-pong oscillations and trapped wandering inside dense clusters until truncation (Tmax = 100).
💬
Open Research Need Identified by the Authors
"For simplicity, we have considered a memory-less search procedure that is akin to a biased random walk. This means that the agents cannot react to the unsuccessful exploration of a given region [...] and the same distribution over actions will apply independently of the historical trajectory."
— Pisacane et al. (2024), Section 6: Future Work

Explicit Recommendation: Extend the forwarded packet to encode visited-node history (e.g., via recurrent neural representations) so agents learn to avoid unproductive cycles.

Primary Research Question
How can decentralized graph routing agents prevent action cycles and community trapping under partial local visibility?
Next Step: To understand how to represent search history inside a compact message packet, we turn to two complementary paradigms from adjacent graph-search literature.
06 • Literature Insight 1 — M-Walk (1 / 2)

M-Walk: Problem Formulation & MDP Setup

"M-Walk: Learning to Walk over Graphs using Monte Carlo Tree Search" — Shen, Chen, Huang, Guo & Gao (Neural Information Processing Systems (NeurIPS) 2018)

🎯
Problem & M-Walk Framework

To solve multi-hop Knowledge Base Completion (KBC) without intermediate path labels, the authors introduce M-Walk, a novel Reinforcement Learning (RL) framework that integrates a Deep Recurrent Neural Network (RNN) state encoder with Monte Carlo Tree Search (MCTS).

  • History-Dependent States: Looking only at the current entity is ambiguous—the agent needs the initial query and prior traversal steps to decide where to move next.
  • Sparse Delayed Rewards: Feedback is given only at the end of a walk (+1 for the true target, 0 otherwise), causing standard RL exploration to fail.
⚙
Markov Decision Process (MDP): State & Action
  • State (Recursive Path History): Starts from the query and source node, then appends each selected action, newly visited node, and its local 1-hop neighbors and edges at every step.
  • Action (Dynamic Choice Set): At the current node, the agent chooses either any outgoing edge to move to an adjacent neighbor, or STOP to finish and output the current node as the predicted target.
  • Deterministic Transitions: Because the underlying graph is static and known, moving along an edge deterministically updates the trajectory state.
07 • Literature Insight 1 — M-Walk (2 / 2)

M-Walk: Agent Architecture, Algorithms & History Encoding

High-level overview of how M-Walk learns to plan over graphs—and how its RNN state encoder compresses trajectory history.

🧩
M-Walk Agent Architecture & Algorithms
  • Shared Policy & Q-Network: One neural backbone drives both the action policy and Q-value estimates—scoring each outgoing edge and STOP by matching them against the encoded path history.
  • MCTS Trajectory Generation: During training, MCTS runs lookahead rollouts via Predictor Upper Confidence Bounds for Trees (PUCT), balancing learned policy priors with visit counts and rewards.
  • Off-Policy Q-Learning: Updates shared weights across MCTS paths, improving value estimates and the policy together; at test time, MCTS aggregates leaf scores to pick the target.
  • Why Not Direct Transfer: Assumes a centralized, fully known graph for tree lookahead (not 1-hop decentralized routing).
↳
Inside the State Encoder: How History Is Represented
1
Candidate Encoding: Embeds each outgoing edge–neighbor pair available at the current node.
2
Neighborhood Summary: Pools candidate embeddings into one fixed-size summary of local options.
3
Gated Recurrent Unit (GRU) Update: Feeds local summary + chosen action + next node sequentially into a GRU cell to update memory.
4
History Vector Output: Projects the GRU hidden state into a single vector capturing what happened and in what order.
Extracted Concept — Sequential / Order-Based Memory: Stepping chronologically through a GRU encodes history as an ordered chain (v1 → v2 → … → vt), preserving step recency and movement direction.
08 • Literature Insight 2 — PHIL (1 / 2)

PHIL: Problem Formulation & Graph Search Setup

"Learning Graph Search Heuristics" — Pándy, Qiu, Corso, Veličković, Ying, Leskovec & Liò (LoG 2022)

🎯
Problem & PHIL Framework

To automate search heuristics for A* and Greedy Best-First Search without manual engineering, the authors introduce Path Heuristic with Imitation Learning (PHIL), combining Imitation Learning (IL) with a recurrent Graph Neural Network (GNN) in strict O(1) time per node.

  • Sequential Data Dependency: Newly reached nodes depend on earlier heuristic choices, breaking standard independent-sample supervised learning.
  • Constant-Time Budget: Computing node priority must stay O(1) regardless of total graph size so search speed does not degrade on large networks.
⊚
Search Formulation: State & Action
  • Search State (3 Node Sets): Partitions the graph into CLOSE (already explored), OPEN (candidate frontier), and REST (undiscovered nodes).
  • Action (Greedy Expansion): Expands the OPEN node with the lowest predicted distance to target—moving it into CLOSE and pushing its newly discovered REST neighbors (Vnew) into OPEN.
  • Partially Observable Markov Decision Process (POMDP): Observes only newly added frontier nodes Vnew; an oracle supplies true shortest-path distances during training.
Core Design Goal: To avoid re-exploring dead ends and escape local traps without inspecting the whole graph, PHIL maintains a compact memory of the explored subgraph.
09 • Literature Insight 2 — PHIL (2 / 2)

PHIL: Training Algorithm, Architecture & Explored-Graph Memory

High-level overview of how PHIL trains with a shortest-path oracle—and how its recurrent GNN builds an order-independent coverage memory.

🧩
PHIL Architecture & Training Algorithm
  • Frontier-Only O(1) Evaluation: Scores only newly added nodes Vnew using a bounded 1-hop neighbor sample, keeping runtime independent of total graph size.
  • Roll-In / Mixed Roll-Out: Executes initial steps with the learned policy, then collects oracle ground-truth distances along a mixed policy trajectory.
  • Truncated Backpropagation Through Time (TBTT): Updates parameters end-to-end across search steps by minimizing distance prediction error.
  • Why Not Direct Transfer: Centralized search maintaining global OPEN/CLOSE sets and requiring a full-graph oracle during training.
🚀
Inside the Recurrent GNN: How History Is Represented
1
Target-Aware Node Features: Combines each frontier node's features with target attributes and direct feature distances.
2
1-Hop Graph Convolution: Aggregates a bounded sample of 1-hop neighbors into a local structural embedding.
3
GRU Memory Update: Combines each new frontier node embedding with the previous explored-graph memory vector.
4
Permutation-Invariant Mean Pooling: Averages updated GRU states across all nodes in Vnew to form the next memory zt+1 regardless of node order.
Extracted Concept — Coverage / Set-Based Memory: Mean-pooling across explored batches ignores visit order and encodes history as a topological set {vi ∈ Vvisited}, highlighting exhausted communities.
10 Comparative Research Question & Hypotheses

Order vs. Coverage: Comparative Research Question & Hypotheses

Comparative Research Question
Which memory representation,sequential trajectory encoding or set-based topological coverage, better prevents action cycles and community trapping in decentralized graph navigation?
H1
Hypothesis 1: Loop Elimination (General Memory Benefit)

Augmenting the roaming packet with a historical trajectory representation will significantly reduce navigation failures caused by endless cyclic exploration and trapped wandering compared to memory-less routing.

H2
Hypothesis 2: Order vs. Coverage Inductive Bias
  • Sequential Memory: Prevents immediate back-and-forth loops and maintains a consistent forward path across bridge edges.
  • Set-Based Memory: Superior at escaping dense, highly clustered communities by penalizing re-entry into exhausted clusters regardless of visit order.

12 • Section 7 — Experimental Setup & Evaluation

Datasets, Strict Generalization Splits & Evaluation Plan

🕸
Datasets & Leak-Free Splits
  • Real Social Graphs: 5 SNAP Facebook ego-networks (148–532 nodes) with anonymized user attributes.
  • Target-Node Split: 80% train / 10% validation / 10% test (Vtest unseen targets prevent route memorization).
  • Synthetic Modular Graphs: Spatial homophilic networks with tunable density (β) & modularity; tested via Inductive Graph Split on unseen graphs.
⚖
Benchmark Baselines
  • GARDEN (Pisacane et al., 2024): Primary memory-less GAT + A2C decentralized baseline.
  • Action-Masked Tabu Walker: Symbolic k-step backtracking prevention.
  • MLP-A2C & MLP-A2C With Degree (MLP-A2C-WD): RL without graph attention (raw attributes ± degree).
  • Decentralized Heuristics: Greedy, Softmax Distance, Degree Hub, Random Walkers.
  • Centralized Oracle: Dijkstra / Breadth-First Search (BFS) upper bound (Roracle = 1.0).
📈
Evaluation Metrics
1
Truncation Rate (Rtrunc %): Episodes exceeding Tmax = 100 (primary loop/trap failure metric).
2
Mean Oracle Ratio (Roracle): Traversed path length divided by true shortest path.
3
Win Rate (Rwin %): Episodes achieving shortest path among decentralized baselines.
4
Revisit Rate & Cycle Count: Average repeated node visits per trajectory.
Comparison Plan
1. Real-World Benchmark (H1): Compare sequential & set-based approaches vs. all baselines across all 5 Facebook graphs.
2. Structural Stress-Test (H2): Sweep edge density (β) & modularity in synthetic graphs to isolate regime crossovers.
3. Loop & Oscillation Analysis: Decompose failures into 2-step ping-pongs vs. extended cluster wandering.
13 — Potential Risks & Fallback Strategy

Anticipated Technical Risks & Mitigation Plans

Proactive engineering safeguards to ensure valid scientific comparisons even under recurrent optimization difficulties or severe structural shifts.

1
Training Instability in Recurrent RL
Risk

Training GRU networks via RL can become unstable or converge slowly under sparse terminal rewards across horizons up to 100 hops.

Fallback Plan

Freeze pre-trained GAT encoder weights and train only the recurrent Actor-Critic heads; add a small step penalty (-0.01/hop) to incentivize forward progress.

2
Information Loss in Set-Based Memory
Risk

Averaging all visited node embeddings over long paths weakens the signal, making recent dead ends hard to distinguish from older nodes.

Fallback Plan

Restrict Deep Sets pooling to a sliding window of the last W visited nodes, or apply attention/degree-weighted pooling prioritizing structural hubs and bridges.

3
Overfitting to Training Paths
Risk

Recurrent memory policies may memorize specific training corridors instead of learning generalizable loop-avoidance strategies for unseen targets/graphs.

Fallback Plan

Deploy the Action-Masked Tabu baseline (FIFO mask forbidding immediate returns to the last k nodes) as a zero-training, generalization-safe baseline.
