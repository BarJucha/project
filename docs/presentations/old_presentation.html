01 • Core Motivation

Decentralized Graph Search: Comparing Memory Types

🌐 Why Decentralized Graphs?

Graph search is traditionally framed from a centralized perspective with a global view, which is impractical in many real-world applications:

🔒 Privacy Concerns: In peer-to-peer networks, a centralized agent poses significant surveillance and privacy risks.
⚡ Scalability Bottlenecks: Large graphs induce memory strain when storing global routing directories.
Research Question
Does sequential memory encoding or set-based topological aggregation better prevent action cycles and community trapping in decentralized graph navigation under partial local visibility?
👤 Author: Bartłomiej Jucha
02 • Foundations & Research Gap

Decentralized Graph Search & The Literature Gap

Routing a message from source to target without a central coordinator or global map (Pisacane et al., LoG 2024), and the critical limitation of memory-less search.

👁
Anchor Paradigm (Pisacane et al., 2024)

Decentralized search modeled as a collaborative Dec-POMDP without global network visibility:

  • 1-Hop Local View: Agents only observe immediate neighbors and their connecting edges, preserving privacy and scalability.
  • Message Forwarding: The current message holder inspects neighbor attributes and picks the next recipient hop-by-hop.
  • Navigational Signals: Relies on node feature homophily and structural bridge hubs to guide decisions toward the destination.
⚠
Identified Research Gap

The authors highlight a fundamental limitation in their concluding remarks:

"For simplicity, we have considered a memory-less search procedure that is akin to a biased random walk. This means that the agents cannot react to the unsuccessful exploration of a given region [...] and the same distribution over actions will apply independently of the historical trajectory."
— Pisacane et al. (2024), Sec. 6 Future Work

👉 The Core Question: How can the traveling message carry a memory of visited history to break these trapping cycles?

03 • Proposed Memory Types

Addressing The Gap: Comparing Memory Types

To prevent agents from getting stuck in dead ends or cycling in dense communities, I let the traveling message carry a "memory" of where it has already been, comparing two distinct paradigms:

↳
Order-Based Memory

Sequential Trajectory: Remembers the exact chronological sequence of steps taken along the path.

(v1 → v2 → … → vt)
  • Encodes traversal direction, velocity, and immediate backtracking.
  • Detects localized loops and sequence-dependent ping-pong patterns.
  • Sensitive to step order and temporal recency.
⊚
Coverage-Based Memory

Coverage / Topological Set: Remembers all visited nodes as an unordered group, focusing on which areas have already been explored.

{vi ∈ Vvisited}
  • Emphasizes which clusters and neighborhoods are already exhausted.
  • Permutation-invariant aggregation across visited subgraphs.
  • Prevents wandering back into previously explored community traps.
04 • Experimental Setup

Environment, Data & Evaluation Metrics

Empirical framework and quantitative metrics designed to stress-test memory mechanisms against topological bottlenecks and local minima.

🕸
Simulation Environment
  • Dec-POMDP Setup: Simulates decentralized routing with strictly 1-hop ego-neighborhood observability.
  • Episode Execution: Passes message hop-by-hop until reaching target or exceeding truncation limit Tmax.
  • Decentralized Constraint: Preserves node privacy without global maps, coordinates, or precomputed tables.
📊
Network Topologies
  • Computer-Generated Networks: Synthetic graphs with adjustable cluster modularity and densities to systematically induce trapping.
  • Real Social Networks: Real Facebook friendship graphs (100–600 nodes) with actual user profile attributes.
📈
Model Evaluation & Selection

For evaluating models, we consider the following metrics:

1
Mean Oracle Ratio Roracle: the ratio between episode length and the shortest path length averaged over all source-destination pairs;
2
Truncation Rate Rtrunc: % of episodes exceeding the truncation length Tmax;
3
Win Rate Rwin: % of episodes where a given agent obtains the relative shortest path length, with ties broken randomly.
